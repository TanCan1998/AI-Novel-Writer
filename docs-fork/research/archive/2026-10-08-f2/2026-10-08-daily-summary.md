## 🔍 关键发现

### 1. FTS5 unicode61 的中文陷阱
- **现象**：15/15 测试用例召回率 0%
- **根因**：将「林晚在筑基期」作为**一个词元**
- **验证**：通配符 `"林*"` 能匹配（证明是分词问题）
- **解决**：改用 jieba-rs 分词器

### 2. VecStore 的文档误导
- **声称**："hybrid search" / "complete RAG stack"
- **实际**：仅支持向量检索 + 元数据过滤
- **缺失**：`text_search()` / `bm25()` API
- **教训**：不能只看 README，必须验证 API

### 3. LanceDB 的依赖爆炸
- **表面**：~800 行代码（API 简洁）
- **实际**：1680 传递依赖（datafusion 重型）
- **冲突**：迁移目标是**减内存**，LanceDB 增加 50–100 MB
- **教训**：评估新依赖必须看 `cargo tree`

### 4. 基线未充分利用 LanceDB
- **发现**：LanceDB 支持 jieba 分词器（官方文档）
- **基线**：退化为 `LIKE` 模糊匹配（未配置分词器）
- **原因**：Node.js 绑定 API 不完整，或开发者未意识到
- **启示**：Tauri 迁移是重新设计的机会

### 1. 评估新依赖必须看传递依赖树
- **错误**：只看直接依赖（lancedb = 1 crate）
- **正确**：`cargo tree -p lancedb`（1680 crates）
- **工具**：`cargo tree --depth 2` 快速预览

### 2. 与迁移目标对齐
- **迁移动机**：减少内存占用（Electron → Tauri）
- **LanceDB 冲突**：datafusion 增加 50–100 MB
- **决策原则**：技术再好，与目标冲突就放弃

- **验证**：查看 API 文档 + 依赖树
